# AI 发展的太快了

做一个简单的对比，我现在实习所在的公司已经从三个月前 AI 提效 30% 到搭建智能 agent （炼化项目组成员为skill，搭建一个工作流取代一部分工作，现在已经开始）；but 校内，大家还是用网页或者桌面端的通用模型问问题，很大一部分人甚至没用过 agent ，还有一部分人代码失控了（即代码都是AI写的，自己不会改），究其原因，我总结为一点，学生的知识库太小，不会写代码（你真的会写代码吗，学嵌入式真的写过很多代码吗），不会使用工具。这些问题我会娓娓道来



# 知识库太小

知识库太小的很大后果是，AI 解决问题的时候会脱缰，即你没法定位问题到底在哪。以一个 uart 传输问题为例，发送机和接收机通信不成功，AI给出反馈：

1、硬件故障：接线引脚不对，硬件损坏

2、代码错误：代码问题，波特率设置

也许你会解这个问题，也许你不会。但当你检查一遍过后，还是不行，有没有考虑过“共地”的问题呢，我想可能很多人都不了解串口是否需要接电源线，ttl,com,usart这些可能也没人关心是什么意思

学的太少，学的太浅，可能校内繁忙的事务和大学生的安逸可能使你在努力过后反而不想学了。问题很正常，这里用最简单直白、不绕弯子的话给出你一条路子：网课按下 end ，开始做一些别的事：

例如买一块 rk3506 ，不在止步于 stm32 的世界。

学习Linux，深入学习嵌入式 Linux 。（这里我推荐陈莉君老师的《Linux内核设计与实现》作为启蒙书）

多问多找多尝试，并且开始对自己闭环总结。（这里就像moba开新地图一样，如单片机地图开的差不多，也要去开别的地图，不然等级上限只有那么高。并且你的系统提示里可能只有单片机、嵌入式Linux这些地图，没有关系，你看完的只是网上缺胳膊少腿的课，只是揭开了嵌入式的冰山一角）
